# Development tools

Every tool that builds, checks or tests the project: its version, what it is used for, where it is
installed and called, the options that matter, and the reason for the choice where the repository
states one ("not stated" otherwise). This document describes what the repository does today.

Sources of truth:

- the versions are pinned in [`tools/toolchain.env`](../../tools/toolchain.env) and
  [`tools/requirements.txt`](../../tools/requirements.txt); a change to either is its own pull
  request ([`tools/toolchain.env`](../../tools/toolchain.env), header);
- `./x toolchain check` compares the tools found on the machine with the pins and fails on a
  different version (`tools/mpfs-env.sh`, `mpfs_toolchain_check`);
- the options are those of the project files (`examples/*/app.gpr`, `libs/mpfs_pac/mpfs_pac.gpr`,
  `tests/host/report/report.gpr`, `tools/stack_report/stack_report.gpr`,
  `tests/prove/sample/sample.gpr`), of `examples/common/bare_build.sh` and of the scripts named in the
  tables.

The pin of the Alire crates `gnat_riscv64_elf` and `gnat_native` is the version of the Alire package,
which is not the version the compiler reports: the package 15.3.1 contains GCC 15.3.0
(`tools/mpfs-env.sh`, `mpfs_toolchain_check`).

Where the tools are installed: the Alire toolchains below `MPFS_ADA_TOOLCHAINS` (default
`~/.local/share/alire/toolchains`), every other tool below `MPFS_TOOLS_PREFIX` (default
`~/.local/share/ada_mpfs/tools`) in a directory named after the tool and its version (svd2ada: its
commit), so that a version is never installed over another one (`tools/mpfs-env.sh`).

## Compiler switches

The switches are in the project files; nothing adds to them on the command line except the scenario
variables of `./x build` (hart, privilege model, profile, hart set).

| Project | Ada switches | Other |
|---|---|---|
| `examples/bare_hello`, `examples/pmp_probe`, `examples/report_test` (`app.gpr`) | `-O2 -g -gnat2022 -gnatwa -gnatwe -gnaty -ffunction-sections -fdata-sections`, with `STACK_ANALYSIS=1` (`./x stack`) also `-fstack-usage -fcallgraph-info=su,da` | `Target` `riscv64-elf`, `Runtime ("Ada")` `light-polarfiresoc`. Common to Ada and assembler: `-march=<arch> -mabi=<abi> -mcmodel=medany`, with `rv64imac_zicsr_zifencei` and `lp64` for the E51 and `rv64imafdc_zicsr_zifencei` and `lp64d` for the U54. Assembler (`Asm_Cpp`): the common switches and `-g`. |
| `libs/mpfs_pac/mpfs_pac.gpr` | Generated sources: `-O2 -g -gnat2022`. Hand-written sources: `-O2 -g -gnat2022 -gnatwa -gnatwe -gnaty`; each one must be listed in the project, and `./x pac check` fails for one that is not. | The target and the runtime are those of the project that withs it. |
| `tests/host/report/report.gpr` | `-g -O1 -gnat2022 -gnatwa -gnatwe -gnaty` | Native. |
| `tools/stack_report/stack_report.gpr` | `-g -O1 -gnat2022 -gnatwa` | Native. |
| `tests/prove/sample/sample.gpr` | `-gnat2022 -gnatwa -gnatwe` | Native, for gnatprove. |

What the switches mean: `-gnat2022` Ada 2022; `-gnatwa` all warnings; `-gnatwe` warnings are errors;
`-gnaty` "the standard style set of GNAT" (`docs/coding-standard.md`). `examples/STYLE.md` requires
`-gnatwa -gnatwe` of every example, "generated code is exempt". The repository states no further
reason for `-O2`, `-O1` or the section switches: not stated.

The bare images are linked by `examples/common/bare_build.sh` (`bare_link`) with
`riscv64-elf-gcc -nostdlib -static -T place-lim.ld -Wl,--gc-sections -Wl,--no-warn-rwx-segments`,
a map file, and `--defsym` for the hart mask, the stack size and the memory region lengths; the
compiler driver can be replaced with `BARE_CC`. Binder and runtime are not used for these images
(`examples/common/bare_build.sh`, header).

## The RISC-V compiler for assembler and linking

The compiler driver `riscv64-elf-gcc` comes with `gnat_riscv64_elf`. It is used

- by gprbuild for the `Asm_Cpp` sources (`start.S` and the others of the images), with the switches
  above;
- by `bare_link` to link the bare images;
- by `hw/run_image.py` and `hw/run_probe.py` to assemble and link the small trap handler and the
  probe programs of `hw/` (`-march=rv64imac_zicsr -mabi=lp64 -nostdlib`), found by `hw/lab.py` in the
  pinned version below `MPFS_ADA_TOOLCHAINS`; another version, or none, is an error (`hw/README.md`).
